% Overall architecture of SectorQ (Section 3.1): one loop that runs for every window, at run time.
%   top     one window on four nodes: every node keeps its sectors in host memory, its GPUs take them one
%           at a time, and the output leaves the GPU already divided by the rows of the next window;
%           nothing moves between nodes while the window runs
%   bottom  runtime re-sectoring: the rows and the number of sectors of the next window are decided from
%           the live terms (a sample of them and their count) and the next gates, every window; the rows
%           go back up to the GPUs; the exchange at the boundary puts every next sector on its node
% A sector has the color of the node that owns it (sector d lives on node d mod 4). The numbers are those
% of window 9 of the 127-qubit kicked Ising run on 16 GPUs (logs/pp_e11-59488608.out): 158.9 million terms,
% 127 rotations, generator rank 127, 127 valid rows, 6 rows chosen, 64 sectors, largest sector 1.01 times
% the mean. Code: the main loop of src/engine/pp_engine.cpp (sample, planShared, Worker::run, exchangeBuckets).
