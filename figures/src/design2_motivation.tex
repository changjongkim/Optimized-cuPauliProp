% Motivation (slide 2 of the deck), second style (the look of the ScaleQsim paper).
% What the figure shows:
%   Left:   the rule. The same term (Pauli string X Z Y I) is created on two GPUs with the coefficients 0.7e-4
%           and 0.6e-4; the cutoff is 1e-4. (1) Truncating on each GPU drops both pieces, the term is lost and the
%           answer is wrong. (2) Merging first gives 1.3e-4, which is above the cutoff, the term is kept.
%           Table: kicked Ising with 22.5 million terms; without a merge across GPUs the value is 0.1675 on
%           4 GPUs and 0.189 on 16 GPUs, the correct value is 0.1531.
%   Right:  the two existing ways to merge across GPUs. (1) cuPauliProp's distributed mode merges and
%           redistributes globally after every gate: 22 collective calls per gate on every GPU, 2.9 s on 1 GPU
%           and 71 s on 16 GPUs for the same 22.5 million terms. (2) Merging only before a truncation keeps the
%           unmerged copies in GPU memory: 2 of the 7 circuits run out of memory on 16 GPUs.
%           Below the two boxes: what each way gives up.
%   Bottom: what is needed (a new term and its merge partner always on the same GPU) and what SectorQ does.
% Message (one sentence): the same term is created on different GPUs and must be merged before it is truncated,
% and the two existing ways to do that give up either communication or memory.
% The two coefficients are an illustration (the cutoff is that of the measured setting); every other number is
% measured (the sources of the figures deck/n03 and deck/n07 cite the logs).
% Colors: blue cell = the Pauli string of the term, gray cell = a term, hatched cell = an unmerged copy,
% khaki = a GPU, teal = the global step, yellow = what is needed, green = the good outcome,
% red = the dropped pieces, the wrong values and what each existing way gives up.
