\section{Related Work}
\label{sec:related}
We discuss the algebraic partition methods and simulation systems relevant to window-conserved sectors, run-time row selection, and host-memory execution.

\subsection{Partitions for Distributed Simulation}
Prior methods identify invariant operator subspaces or group operations to reduce communication.
Their partition constraints depend on the represented state or operator.

\noindent\textbf{Conserved Operator Subspaces.}
Bravyi et al. identify binary symmetries of fermionic Hamiltonians and remove qubits after selecting a symmetry sector~\cite{bravyi2017tapering}.
West et al. describe a commutator graph whose connected components identify invariant operator subspaces under a set of generators~\cite{west2025graph}.
Both methods establish algebraic conditions for independent evolution.
\SectorQ uses the ordinary binary inner product to construct labels invariant under generator XOR.
These labels partition Pauli strings and are distinct from the symmetry eigenvalues used for qubit removal.
A sector can also contain multiple connected components of the commutator graph.
The system requires a partition conserved over a finite gate window and replaces it at the next boundary.
This finite-window constraint permits nontrivial partitions even when all retained strings have identical values under the full circuit's conserved parities.

\noindent\textbf{Fixed Linear Partitions.}
The partition label in paulistrings-rs is a binary matrix multiplied by a Pauli bit vector~\cite{paulistrings}.
Its linear map identifies one communication partner for each nonlocal generator delta, and local coset execution processes independent groups of strings.
The documented rows remain fixed during a run.
Automatic row selection that considers balance and remote work is listed as an open problem.
The parallel iQCC implementation similarly assigns Pauli words to processes through a bitmask and computes product destinations through XOR~\cite{genin2025chemistry}.
These mappings determine destinations even when a product requires remote communication.
\SectorQ additionally requires every selected row to annihilate every generator of the current window.
The resulting sectors contain all contributions required for local merge and truncation throughout that window, with rows selected again at the next boundary.

\noindent\textbf{Staged State Vector Simulation.}
H\"aner and Steiger group and schedule gates to reduce communication in a distributed simulation of 45 qubits~\cite{haner2017petabyte}.
Atlas partitions circuits into stages with an integer program, selects kernels with dynamic programming, and supports host-memory offloading~\cite{xu2024atlas}.
These designs process a fixed state-vector index space across groups of gates.
Pauli propagation has a variable string population because rotations create terms and merge and truncation operations remove them.
A partition must preserve contributions to equal strings before truncation, while its load balance depends on the retained operator.
\SectorQ derives locality constraints from window generators and selects execution granularity from sampled terms.
Host-memory execution uses these sectors as GPU tasks, and any subdivision must remain valid for the unfinished operations.
The storage and scheduling mechanism consequently depends on the operator partition as well as the gate grouping.

\subsection{Pauli Propagation Systems}
Existing systems optimize propagation kernels, distributed storage, or repeated observable evaluations.
These optimizations provide different execution and numerical conditions for comparison with \SectorQ.

\noindent\textbf{Distributed CPU Propagation.}
ORQA demonstrates propagation on Fugaku with up to one trillion Pauli strings and $2^{17}$ processes~\cite{orqa}.
Its structured enumeration of string bits limits communication partners while maintaining balance.
The distribution map determines remote updates as propagation advances through generators.
MonoProp provides distributed Pauli and Majorana propagation through a C++ implementation with Python interfaces~\cite{monoprop}.
Both systems support operator storage across CPU nodes.
\SectorQ uses distributed host memory for sectors and executes their windows through single-GPU propagation kernels.
Its partition confines the window's equal-string contributions to one sector before GPU execution.
The evaluation compares equal node counts with explicit CPU rank and thread configurations.
The ORQA measurements use our reproduction, and MonoProp's different truncation rule requires separate interpretation of its timing and approximation error.

\noindent\textbf{Propagation Libraries and GPU Kernels.}
Sparse Pauli dynamics and PauliPropagation.jl develop observable simulation and coefficient truncation methods~\cite{begusic2024fast,rudolph2025pauli}.
Quantinuum's SPD provides GPU execution, while Qiskit's Pauli propagation package supports Clifford operations, Pauli rotations, and noise channels~\cite{spd,qiskitpauliprop}.
NVIDIA's \cuPP provides sparse Pauli operations on GPUs and a distributed mode~\cite{cupauliprop}.
\SectorQ uses its single-GPU operations for rotations, merge, and truncation within a sector.
The library determines the arithmetic, and the runtime determines the window partition, sector placement, and host-memory transfers.
The evaluation compares the resulting system with original-circuit distributed \cuPP and separates Clifford preprocessing and deferred deduplication from sector execution.
The single-GPU measurements also identify configurations where other libraries execute faster.
The distributed mechanism addresses operator placement and merge locality beyond the execution of individual library operations.

\noindent\textbf{Repeated Evaluations and Gradients.}
PADO-Pauli compiles circuits and observables into sparse matrices reused across batches of parameter values and supports gradients through PyTorch~\cite{kim2026pado}.
This compiled representation amortizes preparation over repeated evaluations during variational training.
Backpropagating Pauli Propagation develops gradient evaluation with the computational complexity of forward propagation and reduces memory requirements through reversibility~\cite{lin2026backpropagating}.
The reported \SectorQ experiments measure one forward observable propagation for a specified circuit and coefficient cutoff.
Its runtime chooses new conserved rows using the retained terms at successive windows.
Batched evaluation and derivative computation introduce additional requirements for representation reuse and intermediate storage.
Their costs require measurements that include the parameter batch or gradient computation, while the present evaluation measures distributed propagation time and capacity for one retained expansion.
