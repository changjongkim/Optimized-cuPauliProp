% Design, Fig. A (Section 3.1): overall architecture of SectorQ on the running example. Left: Window Formation (circuit
% with windows W_k and W_k+1; the Window Builder folds the Clifford gate H into a frame, so Z3 becomes X3, and groups the
% rotations into windows; between two windows the nodes exchange terms). Middle: node 0 at the boundary of W_k and
% W_k+1, by its hardware. CPU: Runtime Re-Sectoring (a sample of the live terms, gathered from all nodes -> Row Solver,
% the GF(2) kernel of the gates of W_k+1 -> Sector Balancer -> new rows x0, z2, broadcast to all nodes). Host memory:
% the Sector Store, sectors as chunk lists. GPUs: (1) each loads one sector, (2) applies W_k, (3) splits its output by
% the new rows; (4) 00' and 10' return to the store, 01' and 11' go to the Sector Exchanger on the CPU, (5) which sends
% sector d to node d mod N over MPI at the window boundary. Right: every node has the same parts, and every node
% exchanges with every other one at every window boundary.
