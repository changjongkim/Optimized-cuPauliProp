%   W_k 생성자 X0, Z2Z3, Z1Z2, Z0Z1 -> kernel x1, x2, x3, z0+z1+z2+z3 -> 행 r1 = x1, r2 = z0+..+z3
%   W_{k+1} 생성자 X3(H를 거친 Z3), X2, X1, Z0Z1 -> kernel x0, z0+z1, z2, z3 -> 표본 8항에서 (x0, z2)가 2/2/2/2로 뽑힘
%   sector 11(노드 1, GPU 1)의 항: Z0X1, Y0X1 -> W_k 뒤 Z0X1, Y0X1, Y1, Z0Y1Z2, X1Z2 (Y0Y1Z2는 잘림) -> 다음 sector 00', 10', 00', 01', 01'

% 구성 요소 이름(본문에서 기울임): Window Builder, Sector Store, Sector Executor, Runtime Re-Sectoring(Row Solver, Sector Balancer), Sector Exchanger.
% 차이를 적을 상대: 3.2 고정 parity 분할(paulistrings-rs)·hash 분배(ORQA, iQCC)와 state vector의 stage 분할(Atlas: 진폭 자리가 고정이라 합치기 문제가 없음),
%   Z2 대칭(tapering)과 같은 선형대수임을 인용; 3.3 실행 전에 정하는 stage(Atlas ILP)와 고정 행(paulistrings-rs: 균형은 open research);
%   3.4 모든 항을 GPU에 두는 방식(cuPauliProp), 분할 하나를 장치 하나에 묶는 방식(paulistrings-rs P <= 64 = rank).
% 도입 문단(3-4문장): 2.2의 두 도전(gate마다 전역 단계, GPU 메모리에 묶인 용량)과 표 2의 요구사항에 대해 SectorQ가 답하는 세 가지
%   (무엇으로 나누나: 구간이 보존하는 parity / 언제 고르나: 실행 중 / 어디에 두고 어떻게 옮기나: host memory, 경계 교환).

\subsection{Overall Architecture}
% 도입: 그림 fig:overview. 두 단계 - Window Formation(회로마다 한 번), Window Loop(구간마다, 실행 중).

\noindent\textbf{Window Formation.}
% Window Builder: Clifford gate를 frame에 모아 뒤 rotation의 생성자를 바꾸고(예: H 뒤의 Z3 -> X3), 처리 순서의 rotation을
% 생성자가 n차원을 넘기 직전까지 한 구간으로 묶음. 구간 경계는 truncation 직후로 맞춤. frame은 노벨티가 아니라 입력 단계.

\noindent\textbf{Window Loop.}
% 노드마다 같은 고리: (1) Sector Store(host memory)에서 sector 하나를 GPU로, (2) Sector Executor가 구간의 gate를 적용,
% (3) 그동안 Runtime Re-Sectoring이 표본으로 다음 구간의 행을 고름, (4) GPU가 출력을 다음 행으로 나눔 - 자기 sector는 store로,
% (5) 다른 노드의 sector는 Sector Exchanger가 구간 경계에서 보냄(sector d -> 노드 d mod N). 모든 결정은 실행 중에 내림.

\subsection{Window-Conserved Parity Sectors}
% 도입(N1): 합칠 짝을 모두 모아야 자를 수 있다(R1-R3). 구간의 모든 gate가 보존하는 parity로 나누면 짝이 늘 한 sector에 있다(그림 fig:sectors).
% 차이: state vector의 stage(Atlas)는 진폭 자리가 고정이라 이 문제가 없음; 고정 parity(paulistrings-rs)는 행을 깨는 gate마다 항을 옮김.

\noindent\textbf{Rows Conserved by a Window.}
% 항 = 2n bit(x, z), 행 r과의 내적이 parity. rotation(생성자 Q)은 P를 P와 P xor Q로 가름 -> r.Q = 0이면 같은 parity.
% Row Solver: 구간 생성자들의 GF(2) 소거로 r.Q = 0인 행 공간(kernel)을 구함. 생성자가 n차원 이하라 kernel은 n차원 이상.
% Z2 대칭(qubit tapering)과 같은 선형대수임을 밝히고 인용. 예: W_k의 kernel x1, x2, x3, z0+..+z3.

\noindent\textbf{Merge Locality.}
% 정리: 구간 안에서 sector의 항이 만드는 새 항은 같은 sector에 남는다 -> 같은 문자열은 같은 sector -> sector마다 합치고 자른 결과 = 전체 결과.
% 증명 스케치(귀납). 예: sector 11의 Z0X1, Y0X1이 W_k 안에서 두 번 합쳐지고 넷이 새로 생겨도 모두 11에 남음.

\noindent\textbf{Exchange Only at Window Boundaries.}
% 구간이 바뀌면 보존되는 행이 바뀜(W_{k+1}의 X1이 x1을 뒤집음) -> 경계에서만 다음 행으로 다시 나눔.
% 회로 전체가 보존하는 행은 0-2개뿐(배경 표 tab:windows)이라 하나의 고정 분할로는 나눌 수 없음.

\subsection{Runtime Re-Sectoring}
% 도입(N2): 어느 유효 행이 고르게 나누는지와 sector 수는 살아 있는 항이 정함(R4, R6). 다음 구간의 행을 지금 구간이 도는 동안 고름(그림 fig:resector).
% 차이: Atlas는 stage를 실행 전에 회로만 보고 정함; paulistrings-rs는 균형을 따지지 않음("open research").

\noindent\textbf{Sampling the Live Terms.}
% 구간이 시작할 때 노드마다 자기 몫의 표본을 뜸(합계 200,000항), 구간의 Clifford 연산만 통과시킴(branch는 무시). rank 0에 모아 행을 정하고 알림.

\noindent\textbf{Balanced Row Selection.}
% Sector Balancer: kernel에서 무작위 행 조합 후보 여럿(8개)을 뽑아 표본의 sector 크기를 세고, 가장 큰 sector가 가장 작은 조합을 고름.
% 예: (z0+z1, z3) 최대 8, (z2, z3) 최대 4, (x0, z2) 2/2/2/2. sector 수 g: 예상 항 수/목표 이하, GPU마다 하나 이상(긴 구간이면 둘), 상한 256.
% 항이 적은 첫 구간은 sector 하나, GPU 하나(R6).

\noindent\textbf{Overlap with the Running Window.}
% 표본은 GPU가 시작하기 전에 뜨고, 행은 GPU가 구간을 도는 동안 CPU가 고름 -> GPU는 출력을 나누기 직전에만 행을 씀, 기다리지 않음.

\subsection{Host-Memory Sector Execution and Exchange}
% 도입(N3): sector를 장치에서 떼어 host memory에 두고 GPU가 하나씩 처리 -> 용량이 host memory를 따름(R5), 항은 경계에서만 이동(R2)(그림 fig:execution).
% 차이: cuPauliProp은 모든 항을 GPU에 둠; paulistrings-rs는 분할 하나 = rank 하나(P <= 64).

\noindent\textbf{Chunked Sector Store.}
% sector = 고정 크기 chunk(262,144항) 목록, chunk는 한 번 pin하고 pool에서 재사용 -> GPU 복사와 MPI가 같은 메모리를 씀. sector 수는 GPU 수와 무관.

\noindent\textbf{Sector Execution on GPUs.}
% GPU마다 worker 하나, 노드의 다음 sector를 가져가 구간을 적용(GPU 메모리: 입력, 출력, 작업 공간). 출력이 버퍼를 넘으면
% kernel의 행 하나를 더 써서 sector를 둘로 나누고 두 절반이 남은 gate부터 이어감(두 절반도 구간에 닫혀 있음, 답은 같음).

\noindent\textbf{Boundary Exchange.}
% 출력을 GPU 위에서 다음 행으로 나눠 chunk에 씀: 자기 노드의 sector는 store의 chunk 목록에 붙이고, 다른 노드 몫은 Sector Exchanger가
% 경계에서 보냄. 라운드마다 (보내는 노드, sector)당 chunk 하나, 보낸 chunk는 pool로 -> 노드가 동시에 가지는 것은 자기 출력과 한 라운드의 도착분.
% 경계의 상태는 checkpoint로도 씀.
